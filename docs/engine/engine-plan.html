CrankMagic · Development plan · 2026-09-20

Retiring Forge for a rules engine of our own

A deterministic, plain-JavaScript Commander engine under game/engine/ that plays any hundred Commander-legal cards a player brings, built behind the bridge and journal contracts the table already speaks, verified against Forge while it still exists, then Forge and the Java runtime removed.

Measured on Personal-HP against main at ca4aca0 and Forge 58bcd59 (2.0.15-SNAPSHOT). The executable version of this plan is docs/engine/PLAN.md in the repository; this page is docs/engine/engine-plan.html beside it.

Recommendation. Build it, in three measured tiers that are the build order and not three finish lines: the seven live decks first (477 cards, 64 effect primitives), the 2,367-card library second, the whole Commander-legal pool third (roughly 28,000 to 30,000 cards; the exact count is fixed by the first Scryfall pull). At pool scale, card definitions come from a template parser, then a Claude-API compiler, then hand-authoring for the residue, with a per-card support ledger and a fuzzing harness that plays random legal decks on both engines to find what no human game would. Go live on a closed vocabulary of the 40 most-used primitives and the families 20 or more cards use, which reaches 80.5 percent of the pool; the next 40 primitives are enhancement 1 (94.3 percent) and the remaining 112 are enhancement 2. Keep Forge as the default engine behind a flag until the go-live gate, use it only as a behavioral oracle, move it out of the product at go-live and keep it as a local oracle through the enhancements. Never copy or translate its scripts. Estimated at 24 to 43 agent sessions to go-live and 7 to 14 more for the enhancements. All seven decisions are answered; the plan waits on one condition.

Start condition and release shape. Nothing here starts until Track V is fully live, with live games 100 percent operational on the Gallery redesign through Play. Then this plan and the separately scoped cloud-host migration kick off together as one major product release; the cloud plan will be updated to reflect this one. The engine is built for the local host first and is kept cloud-ready from the first commit. Rob owns the totality of CrankMagic, the play engine included, under the repository's Source-Available License, for personal use now and potential sale later; "product enhancements" here mean CrankMagic releases, not engine-only drops.

Any hundred cards

Hand-writing a definition and a scenario per card is how the first 477 shape the schema. It is not how 30,000 get done. From the library onward, definitions come from a pipeline in order of trust, and every card carries a record of how far it has been proven.

Default
A Claude-API compiler, the default for every card. Schema as the tool definition, oracle text, the pre-pass result and the primitive catalog in; a script out. Every result is schema-validated, smoke-tested in a fixture game, checked for what it reveals against the projection, and, while Forge exists, differential-checked in fuzzed games. The key comes from Windows Credential Manager, the way the OpenAI pilot's does, and never touches a file, page, URL or log. Cost and pass rate measured on a 200-card sample first.
Pre-pass
A deterministic template parser from oracle text. Keyword lines; "When, Whenever, At [event], [effect]"; "[cost]: [effect]"; "[selector] get +N/+N"; "as long as"; "you may"; "unless"; "instead". Its partial result is handed to the compiler as a hint. Keyword-only and vanilla cards need no API call at all.
Wins
Hand-authored definitions win wherever one exists. Rob's uploads dropped into a hand folder, definitions worked out with Claude in chat, the residue the compiler cannot make pass, and every adjudicated divergence. Tier 0 is hand-authored because it shapes the schema.
Ledger
data/engine/support.json. Per card: verified (scenario or adjudicated differential evidence), compiled (schema and smoke only), or unsupported; the oracle-text hash it was compiled from; its source; its evidence. Shown per card at prepare. A changed oracle text demotes the card until it is recompiled.
Fuzz
Random legal decks, seeded games, both engines. Singleton, color identity, a random commander; random-legal pilots; the same decisions replayed on Forge while it exists. Every exception and divergence is filed with a minimized reproduction. No human plays 30,000 cards; this does, at roughly a thousand games an hour on Personal-HP.
Refresh
A set-refresh workflow modeled on Load Live. Pulls the Scryfall bulk, diffs oracle ids and text hashes, updates the banned list, marks changed cards unsupported, commits the data and lists what needs compiling.

The honest form of "any hundred cards": every Commander-legal card has a definition, measured play requires every card at the table to be verified, casual play can seat compiled cards behind a visible label, and unsupported always blocks. That is decision 6.

Testing strategy

  • Kernel units per rules module, each test naming the Comprehensive Rules clause it proves, written before the module.
  • Card scenarios, at least one per definition: a starting position, decisions, assertions on the projection. The definition PR adds the scenario first.
  • Properties: determinism, termination under random-legal play, no hidden information in any projection, no action outside the enumerated set ever accepted, a retried action applies once.
  • Contract: the envelope, the eleven modes and the event kinds reports consume, pinned by a suite alongside the existing bridge-parity and decision-ui suites.
  • Differential: Forge versus engine on recorded decisions, local only, evidence committed.
  • Live: a real table to turn 3 with a journal, a finished game, a four-seat lobby, per readiness §10 and §12.
  • Performance: the budgets above, asserted by a suite that skips only when its flag is unset.

Licensing the engine

Rob's intent is full ownership of the totality of CrankMagic, the play engine included. The repository's license already does that: it vests the whole of the software in him and lists in §4 the only things it cannot, which are the GPL adapter and third-party content and data. The engine needs no new license; it needs the existing one applied cleanly and the one carve-out that is code removed. After go-live, everything in the product that is code is Rob's, and everything that is not is third-party content kept separable by path.

  • File headers. Every engine file opens with Rob's copyright line pointing at LICENSE; a test fails any engine file without it or carrying another license's identifier.
  • LICENSE §2(c) adds the rules engine and its card definitions to the parts that may not be incorporated elsewhere. §4(a), the GPL exception, is deleted at go-live, and the notices replace the Forge section with a historical note that no Forge code or data remains.
  • An ADR records the clean-room rule, the provenance of compiled definitions under the Anthropic commercial terms in force at the time (cited by date and confirmed before the first compile run), and the provenance of hand-authored ones.
  • Wizards' content, and keeping the option open. CrankMagic, engine included, is Rob's. Card names, oracle text and rules text are Wizards of the Coast's, and the Fan Content Policy prohibits commercializing fan content. CrankMagic is for personal use unless Wizards is interested. Rob wants to be able to disentangle their content from his IP easily if that conversation happens, provided it is not a heavy lift. It is not: the kernel never needs card text and every definition already lives in the card directories with its oracle-text hash, so the separation is a naming convention the design already has, held by a light check at no extra cost. Disentangling, if ever wanted, is a directory exclusion when packaging. Nothing in the plan is gated on it.
