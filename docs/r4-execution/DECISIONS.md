# Execution decisions

These decisions implement the revised plan Rob approved. Source rulings remain visible in `source/`.

| ID | Resolution | Reason |
| --- | --- | --- |
| EX-01 | Create integration before S0; do not merge foundation alone to main. | Tokens and adapted screens should reach main together. |
| EX-02 | Coordinator starts immediately and merges dependencies throughout the effort. | D1 must integrate before dependent Play work can proceed. |
| EX-03 | One writer handles D1, A, B, C and D2 sequentially; reviewers can work in parallel. | Those packets share board functions, CSS and tests. |
| EX-04 | HUD size is a continuous 100-200% slider, previews live and saves on release, per device. | Preserve the repository's standing size-control rule and device-specific fit. The account-synced segmented proposal is not adopted. |
| EX-05 | Board captions are at least 15px at scale 1; general UI text is at least 12px. | The CH-31 11-12px line contradicts the r4 HUD scale. |
| EX-06 | Interaction transitions use the 160ms system duration; reduced motion is immediate. | The CH-12 250ms slide conflicts with the global motion contract. |
| EX-07 | Keep a compatible palette/register representation and deterministic migration of historical preferences. | The supplied application script and packet use different theme names. Never lose a valid saved preference or flash an unrelated theme. |
| EX-08 | Cancel clears an unsent draft; Don't is offered only when the engine permits declining; submitted Undo is server-authorized. | Mandatory effects cannot be skipped and hidden information cannot be rewound by the UI. |
| EX-09 | Separate Admin UI from backend authorization; v1 feature-switch and health displays are read-only. | The audit's first slice is read-only. Editable production switches are not silently added by a broader packet. |
| EX-10 | Retain newer Play backgrounds, graphics and Planned Changes behavior from main. | The packets were written against an older snapshot. |
| EX-11 | Extend existing untap, land take-back, sharing and game-record paths before creating replacements. | Several packet requests already have tested foundations. |
| EX-12 | Preserve meaningful existing assertions when migrating supplied tests. | Replacing tests wholesale must not remove behavioral coverage. |
| EX-13 | Stage source commits from the integration branch only after combined acceptance. No production release. | Preserve one release owner and a reviewable rollback target. |
| EX-14 | Apply the 15px scaled HUD floor to game-state captions and facts; preserve explicit component typography for Coach and Camera forms, with the general 12px floor. | M's blanket board-DOM sentence conflicts with the specified 36px Coach header, 22px Questions row with 13px text, and 13px Camera labels. Concrete component metrics take precedence over that blanket sweep; game-state text does not inherit those exceptions. |
| EX-15 | Keep the legacy 16:9 mat shape in Table and Focus where it fits both complete zone rows and their chrome. When the scaled header and battlefield/lands row minima cannot fit, grow the mat vertically and scroll its viewport. Preserve card aspect ratios, column widths, normal row gaps, horizontal fit and hand clearance. | Actual four-seat captures showed Lands reduced to clipped strips; the real-room Focus1280×800 case also placed its Library draw control behind the hand. CH-33 explicitly requires at least one usable row on each side of the divider; that requirement takes precedence over the older mat aspect ratio. Geometry checks must cover the conditional minimum rather than discard aspect checks everywhere. |
| EX-16 | Measure the public card badges to establish a readable minimum. In Table, retain the continuous 60–160 control by applying its natural size delta above that minimum when needed; keep Hand sizing independent and card proportions intact. | A simple maximum of natural width and caption minimum made the whole Table range flat at HUD200. Both original endpoints must change rendered size, fit their captions and stay within the layout. Requested scale percentages can therefore include a readability offset instead of implying an exact raster ratio when that minimum binds. |
| EX-17 | Tapping any card rotates it 30 degrees inside its existing slot. Keep card spacing, slot sizes and neighboring positions unchanged; rotated corners may overlap or tuck under adjacent cards. | Rob explicitly clarified this during execution. It supersedes the coordinator's stricter rotated-footprint containment/recentering checks. Untapped badge readability and access to controls remain required. |
| EX-18 | The CrankMagic wordmark is Cinzel 600 in capitals at .08em, in the new `--color-brand` antique gilt (every skin and register); the Oxanium subset and its notice are retired. Supersedes CH-03's "Wordmark untouched; Cinzel never on the app name". | Rob, 2026-10-26: "I liked the typeface Cinzel. I thought you were changing the app name. Use the typeface from the mock-up you had on the app name CrankMagic (I don't like it's current font or font color)." |
| EX-19 | Deck tile: the favorite star sits beside the stage pill in the top-left row; the select tick and the deck menu wait at the right under the mana pips and appear on hover, focus or tick, so nothing moves; a favorite is filled ink, not the accent. | Rob, 2026-10-26: "moving the favorited icon to next to the status (e.g. Boxed, Defined, etc.)". |
| EX-20 | Planned Changes: every Add to Box can be ticked and needs no take-out. A To Buy Final ticked is recorded as owned in the box; an Ordered one is marked arrived and goes in; an Upgrade naming nothing joins the list. A Substitute whose card went in stays a Substitute with no live card, unless a Reserved seat lost its Substitute, when the two are paired (several Substitutes for fewer seats: largest mana value first; model command `holdSeat`). A list or box past 100 reads Building and Over, is never Boxed, and the table refuses it; edits to a locked list no longer require exactly 100 (locking still does). | Rob, 2026-10-26, on Planned Changes and decks over 100. |
| EX-21 | Play camera: Tilt is the camera's angle to the scene's floor, 0–90: at 0 the lowest view, a seated player's eye (the camera 45 degrees from straight down); at 90 perpendicular to the floor, straight down; the default 10 is the 40-degree camera it always had (kept as `cm-board-tilt-v3`; v2 values carry over). A table corner dragged zooms the table with the opposite corner anchored; the sliders are bare ranges whose thumbs reach both ends, their rows 25% closer; a "Reset" text link beside View seats returns every Camera setting to default, card spacing included (it replaces the ⌖ center icon); the device note ("Appearance preview", later "Looks: only on this device") is gone and the Background and Table boxes are shorter in place. The repo's camera tests read the new tilt and Reset. CH-34's Camera redesign keeps these. | Rob, 2026-10-26, with screenshots of the camera menu and the 60-degree table; "0 degrees should have no angle to the floor. 90 degrees should be perpendicular to the floor." |
| EX-22 | The 3D hand shows as many cards as fit at the hand's size, seven at the least, so a wide or zoomed-out window shows more before paging (drawn again only when that changes what shows); the backdrop video always spans the stage's full width, so no blurred poster shows at the sides. | Rob, 2026-10-26: "I should be able to see at least 9"; "the right side of the background is being blurred out". |
| EX-23 | Play, second round: the hover card shows no power/toughness badge; the top-left life list includes you, first, and the seat whose turn it is in bold after a small turn symbol; an opponent's play card stands just past the open left drawer (over the table) and keeps its place at the edge when the drawer is folded, below the whole life list however many rows it has; it is measured where it rests, not mid-entrance, so it is never put away as covering the drawer's own buttons or the control that has the focus. | Rob, 2026-10-26, with two screenshots: the badge "covers part of the text"; "include the user (me) in the top left list"; the play cards "should never overlap the left drawer when its out". |
| EX-24 | The held right-button look rises first (the eye 2% of its height straight up at the farthest place, 1% at the centerline, in by 35% of the motion and given back by 90% as the lean carries it over), reads 30% closer at the end, and while held turns the head after the pointer by the angle the pointer's offset from the press spans in the view, with an 80 ms lag, never past 34 degrees aside, the near horizon above or straight down; letting go takes it home with the rest of the motion. The admin panel is to carry these as settings. | Rob, 2026-10-26: "the camera should move (not look) up slightly ... the zoom that occurs when looking down at the end should be a bit more, maybe 25-35% more, then if I move the mouse while still holding ... it should 'turn the head'". Read "left click" as the held click: the look is the right button's. |
| EX-25 | Mana Pool, a side-drawer module (not in the default layout): Total mana and Available on top, then W U / B R / G C two to a row, each number under its symbol. The room's view carries `manaSources` (game/engine/rules/actions.mjs, manaSources): each of the seat's own permanents with a mana ability that taps it, its ways (what one activation adds, and any mana it costs first), tapped, and ready now. Total counts every source, tapped or not, a source of either of two colors once and a Signet as its two less its {1}; Available counts the ready ones and the mana pool; each color counts the pool's and one for each ready source that makes it, so tapping an either/or source takes it off both. An older room is counted from basic lands, and says so. Mana floating from a Signet is spent first when a spell is cast (the room's quick tap plan; tests/room-mana-pool.mjs). | Rob, 2026-10-26: "a new module available to the side drawers: Mana Pool ... When one that is 'tap for either x or y' is tapped, then both of those colors would go down by one"; "check that when I tap a mana to tap an artifact like Orzhov Signet, it's ... mana are available for spending to cast and prioritized". |
| EX-26 | A card of yours that another player's spell or ability on the stack targets is outlined in red (`--color-required`) with a red glow, while it waits and as it resolves, and says by what in its name and tooltip; a card your own spell targets is not marked. | Rob, 2026-10-26: "cards where I have to take an action if I'm targeted, I should be able to see which card was targeted of mine (a red highlight outline around the card could work)". |
| EX-27 | Apply EX-23's open-drawer clearance in Focus as well. Preserve an outside-mat preview when the measured gap fits it; otherwise place it just beyond the drawer over the mat. A grown EX-15 mat must not force the preview back over drawer controls. | The latest explicit "never overlap the left drawer" request supersedes the older Focus fallback that deliberately covered it when space was narrow. Viewport width alone no longer establishes a physical gap. The existing 1280/2240 cases use actual geometry and retain the available-space behavior without an invented viewport matrix. |

The general undo house rule follows the packet's intended capability, but its availability and window are
defined by the room contract and server checks. UI visibility is not evidence an undo is legal. A default
must not retroactively change an existing game's rules.
