An actual four-player Commander game, played on the table we already built.

Your deck against one, two or three opponents piloted by Claude. Decks from your library, an Archidekt link, a paste, or built by the simulator. One bracket and Game Changer cap every seat adheres to. This page is the plan — and where it can, it runs against your real six decks so you can see what it would actually feel like rather than take my word for it.

From the table background, I select an active deck out of any of my decks and I choose the number of AI opponents… I can set the bracket and Game Changer limits all decks adhere to. Then, using the Claude API and either Haiku or Sonnet, those models are given play style instructions, or they generate play style instructions for those decks, leveraging the graph and the chains and loops that we've defined and designed… Those models then play as the AI for my competition. Period. We're creating the game online here.

Four hard problems, named first

These decide the architecture. The feature list does not.

1 · The engine

There is no rules engine

sim-engine.js opens with “A Monte Carlo model of a four-player Commander game, not a rules engine” and publishes its own simplifications: no stack, no blocking assignment, tokens modelled as extra power, opponents as nine parameterised curves. It is excellent at comparing two versions of one deck. It cannot play a game. A board has to be built, and it is the long pole.

2 · The key

A static page can't hold an API key

CrankMagic is zero-dependency, static, on GitHub Pages, with no server. A key in client JavaScript is readable by anyone who opens the page. Three options weighed below — your key in your browser now, a key-holding Worker the day someone else plays, and a no-key floor that always works.

3 · The cards

30,000 cards can't be hand-written

No plan that needs an implementation per card is a plan. A three-tier ladder answers it: the referee runs the rules, the classifier runs the common effect shapes, and a model adjudicates the rest into deltas the referee validates. That is what makes an arbitrary Archidekt deck playable on day one.

4 · The wait

A model per decision is unplayable

Send every choice to Claude and a game is ~400 calls — minutes of spinner and a bill that scales with how long you play. Asking the model for judgment and leaving bookkeeping to code is ~35 calls and about $0.25 a game. That is not a compromise; it is what makes it shippable.

What CrankMagic brings that nothing else has

The graph

For any deck we already know its loops (untap → tap ability → payoff), its chains (a card that causes what another triggers on), every card's Primary Purpose, its role coverage, and the commander's strategies with per-edge strength. An opponent told “this deck has a four-card untap loop; here are the pieces and the two tutors that find them” plays differently from one handed a hundred card texts. This is the differentiator.

The simulator's ratings

Before the pod sits down we can say whether it is a fair table. Your six decks measure — that spread is real, and it is what the lobby reads.

Bracket compliance that already works

compliance-model.js validates Game Changer counts, mass land denial, extra-turn chains and tutor density against a bracket. “All decks adhere to bracket N” is a function to call, not a feature to build.

The three-tier card ladder

This is how an arbitrary decklist becomes playable without writing 30,000 card implementations.

TierResolved byHowCoverage
1 · rulesthe referee, always zones, turn structure, mana and colour identity, casting cost and commander tax, summoning sickness, attacking and blocking, first/double strike, flying, menace, trample, deathtouch, lifelink, vigilance, haste, lethal damage, the legend rule, commander damage, 0 lifeevery card
2 · shapesthe referee, from card-classify.js the effect vocabulary the classifier already extracts — draw N, ramp N, destroy target, exile, wrath, make N tokens, counter target spell, gain N, mill N, tutor, untap, blink, copy, extra turn, damage N — executed deterministicallymost cards in a typical deck
3 · the restthe adjudicator, validated by the referee the card's oracle text, the board, and a closed delta schema; every returned delta checked against tier 1 and written into the game log with the card texteverything else, including cards printed after the catalog was baked

A tier-3 resolution is exactly the moment at a kitchen table when someone reads a card aloud and the group agrees what it does. The engine's job is to stop the group agreeing something impossible. A card that comes up often gets promoted to tier 2 by teaching the classifier.

The deck brief, and the playbook it produces

The model is not handed a hundred card texts. It is handed what the graph already knows — which is why an opponent here plays like it read the deck rather than like it skimmed a list.

What goes in — assembled by code

COMMANDER   name · colour identity · cost · oracle · its 3 strategies
THE HUNDRED by Primary Purpose, with mana value and a
             one-line effect from the classifier
LOOPS       every cycle of ≤4 cards, each step named, with the
             missing pieces and the tutors that find them
CHAINS      cause → trigger pairs and multiplier edges
SHAPE       curve, lands, ramp/draw/removal counts vs the floors

With no API key the game still plays. The pilot falls back to a heuristic playbook derived from the graph alone — a weaker opponent, but a real one. That floor is why every automated test runs offline and free.

The build, in order

Each one ships something true on its own. The rows are not the same size — G3 is several sessions and everything else is one or two.

A first playable game against a real AI opponent is G0 → G6. The midpoint worth aiming at is G4 + G5: a complete game, four seats, real rules, real opponents, zero API spend.

What I would not build, and why

A rules-complete engine

Split second, layers, replacement-effect ordering, a full priority window on every object — this is where every homebrew Magic engine dies. The referee runs a simplified stack: priority passes only when something is on the stack and a seat holds an instant, flash permanent or activated ability. That covers counterspells and removal responses and nothing else. Said once in the UI, not buried in a tooltip.

Multiplayer against other humans

Server, accounts, reconnection. It belongs with the persistent-app plan, not here.

Hiding information by pretending

A pilot sees exactly what a player at the table sees: every battlefield, graveyard and exile, its own hand, and card counts for the rest. Not your hand. Not the top of your library. Enforced by the referee assembling the prompt — not by asking the model to be fair.

Scraping Moxfield · shipping a key

Moxfield answers a deck API request with 403 to a server and a browser alike, and the paste path is better anyway. And your key stays in your browser until there is a proxy.
