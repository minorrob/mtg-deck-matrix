## 2. Repo conventions and environment gotchas

- **Cache versions.** Every changed `*.js` / `*.css` / `data/*.json` needs its `?v=` bumped in
  `index.html`, `crankmagic.html` and the `SHELL` list in `crankmagic-sw.js`; `crankmagic-app.js`
  also registers `crankmagic-sw.js?v=N`. `node tests/asset-versions.mjs` says exactly which file is
  stale; it passes without `--update` once the version differs from the recorded one.
- **Gates**, all from the repo root:
  `bash runtests.sh -q` (51 suites);
  `UAT_PLAYWRIGHT=/opt/node22/lib/node_modules/playwright/index.js UAT_CHROME=/opt/pw-browsers/chromium-1194/chrome-linux/chrome node tests/uat/crankmagic-journeys.mjs` against `python3 -m http.server 8790` (start the server in the same shell command — background processes die between turns);
  `GEOMETRY_REQUIRED=1 node tests/browser-geometry.mjs` (serves itself).
- **Never `pkill -f "http.server 8790"` in a command that also launches that server** — the pattern
  matches the shell's own command line and kills the run (exit 144). Use `fuser -k 8790/tcp`.
- **Do not edit files while the journey is running**; the browser reloads mid-run and reads half a file.
- **Pinned journeys.** Moving or renaming a control breaks `tests/uat/crankmagic-journeys.mjs`;
  update it in the same commit. `tests/tour.mjs` checks `crankmagic-tour.js` selectors exist.
- **Load Live** for realistic data in Playwright: User Functions → Restore from a backup file →
  `data/live-state.json` → Validate → type RESTORE → Restore reviewed backup. Rebuild the file with
  `node tools/build-live-state.mjs` after editing `data/live-load.json` (`--check` first).
- **Retired modules** (not loaded by `index.html`; do not target them): `deck-page.js`, `app.js`,
  `viewer.js`, `shop-filters.js`, `game-record.js`, `admin-menu.js`. The deck page, Log a game and
  Deck Definition live in `crankmagic-decks.js`; the roster and Shop in `crankmagic-collection.js`;
  the model in `collection-model.js`. `game-record.js` has a usable Wilson interval — load it if you
  use it.
- **GitHub from the sandbox.** `gh` is absent; the MCP tools rate-limit the account after bursts.
  Merging through git works: `git checkout main && git merge --no-ff <branch> && git push origin main`
  (GitHub marks the PR merged). The proxy refuses branch deletion (403) and headless Chromium cannot
  reach `github.io` (tunnel reset) — verify the deploy with `curl`, test on a local server.
- **Commit style.** Subject as a sentence about the change; body in caps-led paragraphs saying what
  was wrong and why this is right; end with the attribution lines the session gives you. No model
  identifiers anywhere in the repo.
- **Squash-merge your own PRs** unless asked otherwise; `#131` and `#132` are merge commits by request.

### P0 (PR 2: "money, to-pull, pull sheet")
