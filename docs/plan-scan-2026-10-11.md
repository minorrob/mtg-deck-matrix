# Scan: cards identified from photos of their info strip (scope and plan)

**Asked for.** Rob, 2026-10-11: a CrankMagic tool that takes uploaded photos of cards' bottom info sections, stacked
and fanned, and runs without an LLM. It gives players guidance up front on photos that extract well: size,
resolution, number of cards, layout, lighting and glare. Its output is:
- a table of the card info, filled from Scryfall;
- a list of the cards it is not fully confident about, for the player to complete;
- the scanned cards, loaded into a **Scans** group, a holding group for the player's scans.

How cards move from Scans to the Bench or a deck is a later conversation.

**Verdict: feasible.** One unknown is measured before any screen is built. Identifying a card from its strip
without an LLM is sound, because the strip names one printing and carries its own cross-checks (§1). The unknown is
how well an off-the-shelf OCR engine reads text about 1.4 mm tall in a phone photo, foil glare included. Phase 0
measures that on 205 strips whose answers are already verified, and its gate decides between Tesseract and a small
reader built for this one font. Everything after the reader is the same either way.

Nothing here is built. Written against `main` e46e3c2.

---

## 1. Why it works without an LLM

Since Magic 2015, every card prints its collector information at the bottom left ([mtg.wiki][strip]):
- rarity;
- collector number;
- a three-letter set code;
- a dot, or a star on a foil;
- language;
- artist.

From March of the Machine on, the number has four digits with the rarity letter in front ("R 0187"). From Magic 2015
up to that set, the number is a fraction followed by the rarity ("187/280 R"). Cards printed before Magic 2015 have
no set code there.

That strip is a label more than prose:
- **The answer space is closed.** Set code plus collector number names exactly one printing, and every valid pair is
  in Scryfall's bulk data.
- **It checks itself.** Rarity and artist are printed beside the number and don't depend on it. A misread number is
  caught when the printing it points to has a different rarity or artist.
- **The alphabet is small and the fonts are fixed:** capitals, digits, a dot and a star. The artist name is the only
  free text.

Measured on 2026-10-11 against Scryfall's default-cards file `default-cards-20261011210554` (109,487 paper
printings):

| Fact | Value |
| --- | --- |
| Paper printings released since Magic 2015, so readable from the strip | 79,084 (72%) |
| Of those, since March of the Machine (the four-digit format) | 36,395 |
| A print index of those 79,084, one row each: set, number, rarity, language, artist, name, finishes, year | 5.6 MB raw, 1.8 MB gzip |
| The same index over every paper printing | 7.7 MB raw, 2.4 MB gzip |
| One-character misreads of a collector number (0/8/6/9, 1/7, 3/8, 5/6 and kin) that land on another real printing in the same set | 193,597 |
| ...that rarity or artist tells apart | 98.4% |
| ...left with the same rarity and the same artist (mostly basic lands and same-artist neighbors) | 1.6% |

The bottom rows are why the cross-checks are required. A bare number read, snapped to the nearest real printing,
would often be wrong. The rarity and artist checks plus the uniqueness rule in §5 cover the 1.6%: for a wrong card to
get through, all three printed fields must misread toward the same other printing.

This is also how Rob's last two photo rounds were done (project docs `photo-extract-41-cards-2026-10-10` and
`photo-extract-15-cards-2026-10-11`):
- **The rounds:** 205 strips in 15 photos, about 14 a photo, 37 of them foil.
- **The method:** an LLM read the glyphs, and a read was accepted only when Scryfall's artist and rarity matched it.
  All 205 were confirmed that way.

The verification half was already deterministic. This tool keeps it and replaces the reading half.

## 2. Scope

**In (v1):**
- A Scan page under Cards. Guidance comes first, then upload of one or more photos.
- A quality check per photo. A photo it can't read is refused, saying what to change (`AGENTS.md`: behavior that
  would break the result is refused, with instructions).
- Processing on the device, in a Web Worker: find each strip, read it, match it against the print index.
- A results table, a Needs you list, details filled from Scryfall, and Save to Scans.
- Photos never leave the device. Scryfall sees only set and number lookups, which the app already makes.
- Any language. Set and number identify the card; the language code is recorded, and the price is looked up for that
  language (`/cards/{set}/{number}/{lang}`).

**Out of v1, and where each part goes:**
- **Cards printed before Magic 2015:** no set code on the strip. They go to Needs you with name search in v1;
  reading the title line is Phase 2.
- **Live camera capture with a framing overlay:** Phase 2.
- **Fanned and loose layouts:** Phase 2, if Phase 0 shows they fail. v1's guidance asks for a straight column.
- **Moving cards from Scans to the Bench or a deck, and copies as individual things (`BACKLOG.md` #4):** Rob's later
  conversation.
- **Condition and grading.**

## 3. Capture guidance: the screen before upload

The page's wording, with the reason behind each line:

| Guidance | Why |
| --- | --- |
| Lay up to 15 cards face up in one straight column. Each overlaps the one below so only its bottom strip (about 1 cm) shows. All cards are the same way up. | 15 strips at the size below fill a portrait photo. Rob's photos averaged 14. |
| Use a plain, matte, mid-tone surface: a gray or blue cloth, or the plain part of a playmat. Not white, black or patterned. | Black borders vanish into black, and a pattern reads as text. |
| Light evenly from the side: daylight near a window, or a lamp off to one side. No flash, and no lamp straight overhead. | Glare is the main failure. It is worst on foils and borderless prints. |
| For foils, tilt the phone or the cards until no strip shows a bright patch. | The star that marks a foil is about a millimeter wide. |
| Use the phone's main (1×) camera, held flat above the column about 20 to 30 cm away, with the column filling most of the photo's width. Tap to focus on the strips. Don't zoom. | Capitals come out about 40 px tall (below). Ultra-wide lenses blur the edges. |
| Take photos at full resolution, as JPEG or PNG. One photo per column, and as many photos as needed. | |

**The pixel math** (assumed here; Phase 0 measures it):
- The strip's capitals are about 1.4 mm tall.
- With the column filling 60% of a 3,024 px wide portrait photo, a 63 mm card spans about 1,800 px, or about 29 px
  per mm.
- So capitals are about 40 px tall.

Phase 0 sets the floor below which a photo is refused.

## 4. How it works

It all runs in the browser, in a Web Worker. It loads only when the Scan page opens and is cached by
`crankmagic-sw.js`. There is no server work and no LLM.

1. **Decode.** Apply the photo's EXIF orientation, and refuse a photo whose short edge is under 2,000 px.
2. **Find the strips.** In a straight column, each card's bottom edge is a strong horizontal edge, and projection
   profiles on a canvas find them without a computer-vision library.
   - Deskew each strip.
   - Draw every strip found as a box on the photo, with the count, so a missed card shows.
3. **Check each strip.**
   - Blur: the variance of the Laplacian.
   - Glare: the share of blown-out pixels.
   - Size: the estimated capital height.

   A strip that fails is marked Retake, and is still attempted.
4. **Read each strip** with tesseract.js:
   - in single-line mode;
   - limited to the strip's alphabet;
   - in both text polarities (white on black borders, dark on light frames).

   Keep each character's confidence.
5. **Parse** with two grammars:
   - `[CURMLPTS] dddd` (March of the Machine on);
   - `ddd/ddd [CURMLPTS]` (Magic 2015 up to it).

   Then `SET [•★] LL`, then the artist. Promo and Secret Lair numbers can carry letters or a star, and the parser
   keeps them.
6. **Match** against the print index, by the rules in §5.
7. **Fill** each matched printing from Scryfall with `scryfall-client.js` `collection()` (identifiers
   `{set, collector_number}`, 75 a request). This gives the name, images, USD prices, finishes, frame and
   treatment.
   - Fix one thing on the way: `collection()` names a missing entry by `entry.name || entry.id`, which is empty for a
     set-and-number identifier. Make it report the set and number.

**The print index.** `tools/refresh.mjs` builds `data/print-index.json` from Scryfall's default-cards bulk file.
- **The download:** 79 MB compressed, at build time only.
- **What it keeps:** paper printings since Magic 2015, one row each: set, number, rarity, language, artist, name,
  finishes, year. That is 1.8 MB gzip today.
- **When:** it refreshes with the rest of the card data (the `crankmagic-refresh` skill).

**Libraries** (npm, read 2026-10-11). Each is vendored into the repository rather than loaded from a CDN, and listed
in `THIRD-PARTY-NOTICES.md`.

| Package | Version | License | Note |
| --- | --- | --- | --- |
| tesseract.js | 7.0.0 | Apache-2.0 | The reader. |
| tesseract.js-core | 6.1.2 | Apache-2.0 | The wasm engine: 30.6 MB unpacked across its build variants, of which one is loaded. |
| English traineddata, fast | | Apache-2.0 | Size measured in Phase 0. |
| @techstark/opencv-js | 5.0.0-release.1 | Apache-2.0 | 14.7 MB unpacked. **Not used**, unless strip finding on fans needs it. |

## 5. Confirmed, or Needs you

A strip is **Confirmed** only when all of these hold:
1. It parses under one grammar.
2. Its set and number are a real printing. Either they were read exactly, or one character was changed, and that
   character's OCR confidence was low. Phase 0 sets the threshold.
3. The rarity letter matches the printing's rarity. L and P are exempt: basics print L and promos print P.
4. The artist read matches the printing's artist. Accents are removed and the surname is matched fuzzily, with the
   threshold from Phase 0.
5. **Uniqueness:** no other printing passes 2 to 4. This sends the 1.6% case, neighbors with the same rarity and
   artist, to Needs you.
6. The finish is known: either the dot or star was read with confidence, or the printing exists in one finish only.

**Needs you** is everything else. Each row shows:
- the strip's crop, enlarged;
- the reason, in words. For example: "The number could be 0315 or 0316: Festival of Embers and Emberheart
  Challenger, both Bloomburrow rares by Cory Godbey."
- up to three candidates, as card images;
- the fields to complete.

**Not a card** covers a strip with rarity T, or one from a token set. These are listed apart.

"Fully confident" means three printed fields agree with one printing and no other printing fits. Phase 0 measures how
often that is wrong, and the bar is never.

**The same printing twice.** If the same printing and finish appears in two photos of one batch, it is flagged, and
the player says whether that is two copies or one photographed twice (`AGENTS.md`: decisions belong to the players).
Two identical strips in one photo are two copies.

## 6. What the player gets

**The results table:** one row per strip.
- Columns: Photo, Strip, Status, Card, Set, Number, Rarity, Finish, Language, Treatment, Price, and the raw read.
  Prices are in USD, formatted `en-US`.
- Totals: strips found, Confirmed, Needs you, Not a card, Retake, and value.

**Needs you:**
- The required fields are Card, Set, Number, Finish, Language and Quantity, prefilled from the best candidate.
- Card is chosen through the client's `autocomplete`, and Set and Number resolve through `bySetNumber`.
- Nothing saves while a required field is empty.

**Save to Scans:** saves the Confirmed rows and the completed Needs you rows.
- Strip crops stay on the device, in IndexedDB, while their entry is in Scans, so "why did it read this" stays
  answerable.
- Whole photos are not kept.

**The Scans group in v1.** This is the builder's default until Rob decides otherwise.
- **The problem with saving them as owned copies.** In today's model (`docs/plan-groups.md`, `collection-model.js`),
  an owned copy sits in a physical group, the Bench by default, and decks reserve free owned copies automatically
  (G3d). So a scanned card saved as an owned copy would land on the Bench at once and could be reserved by a deck
  before anyone checked it.
- **What v1 does instead.** It adds a `scans` group template whose contents are **entries, not copies**, so nothing
  reserves them and no count changes.
  - Each entry carries its print detail: set, number, finish, language, treatment, Scryfall id, batch, photo and strip,
    the reads, and the confidence.
  - The status vocabulary gains **Scanned**. Today a group entry outside To Buy reads Planned.
- **What that buys.** A misread changes nothing about ownership or decks until a person moves it.
- **What waits.** Moving entries to the Bench or a deck, where they become owned copies (with `BACKLOG.md` #4 for
  print-level detail), is the later conversation.

## 7. Phases and gates

### Phase 0: benchmark and core, with no UI

**Build:**
- The print-index step in `tools/refresh.mjs`.
- The scan core, as plain modules that run in Node and the browser: strip finder, reader, parser, matcher.
- `tests/scan-core.mjs`. It covers the two grammars, the confusion set, each rule in §5, and the 1.6% case: two
  same-artist, same-rarity neighbors must not confirm. Break each test once and watch it fail.
- `tools/scan-bench.mjs`. It runs the core over a folder of photos with a labels file, and prints the metrics below.

**The benchmark.**
- **The first set:** Rob's 15 photos from 2026-10-10 and 2026-10-11: 205 strips, 37 foil. They are labeled from the
  Photo Reads tabs of `Treys MtG Card Photo Extract - 2026-10-10.xlsx` and `- 2026-10-11.xlsx`.
- **Rob supplies the photos.** The repository is public, so the photos and labels stay out of git, in a folder on
  Personal-HP named by an environment variable. CI runs on synthetic fixtures.
- **The second set:** Rob then shoots 5 photos following §3, foils and borderless prints included.

**Gate S0**, measured on both sets:

| Metric | Bar |
| --- | --- |
| Wrongly Confirmed | 0 |
| Strips found | 98% or more |
| Confirmed share, Rob's existing photos | 80% or more |
| Confirmed share, photos taken to the guidance | 90% or more |
| Time per 15-strip photo | 3 s or less on a desktop; 10 s or less on a mid-range phone (measured in Phase 1) |

**If a bar is missed:**
- **Confirmed share is short:** replace the reader with a small glyph classifier for this one font, about 40
  classes. It is trained on the benchmark crops plus synthetic renders, and runs in plain JS. The matcher and
  everything after it stay.
- **Strip finding fails on fanned photos only:** v1's guidance requires a straight column, and fans move to
  Phase 2.
- **Anything is wrongly Confirmed:** tighten §5's thresholds until nothing is, and report the Confirmed share that
  costs.

### Phase 1: the Scan page, behind a switch on staging

- **Route:** `#scan` under Cards (`NAV_GROUP`), with the guidance first.
- **Upload:** several photos at once.
  - An iPhone's photo picker is expected to hand the browser a JPEG. Confirm this.
  - A HEIC file that a desktop browser can't decode is refused, with instructions to export it as JPEG.
- **Refusals with instructions:** each names the photo and what to change. For example: "Photo 2: glare across
  strips 4 to 6. Move the light to the side or tilt the cards, then retake it."
- **Processing:** the worker pipeline with progress, and the strips found drawn as boxes on the photo. Zoom on the
  photo is a slider (`AGENTS.md`: sizes are sliders).
- **The rest of the page:** the results table, Needs you, Save to Scans, and the `scans` template with the Scanned
  status.
- **Suites:**
  - `tests/scan-core.mjs`.
  - A browser journey: upload a fixture photo, see N strips, complete one Needs you row, save, and Scans shows N.
  - `tests/feature-wiring.mjs`: `en-US` formatting, USD only, no size buttons.
  - The A11y checks on the new page.
- **Done when** Gate S0's bars hold on a phone over staging, and Rob scans one real purchase end to end.

### Phase 2: better capture

- Live camera, with a framing overlay and a live quality meter.
- Fanned and loose layouts, if Phase 0 deferred them.
- Cards printed before Magic 2015, by reading the title line.
- An export in the Master's photo-extract layout (`xlsx-writer.js`). This would replace the reading half of the
  `mtg-photo-extract` skill, leaving the LLM only the 1-10 rating.

**Sizes.** These are guesses until Phase 0 measures; the reader's accuracy is the one unknown that moves them.
- Phase 0: one or two sessions.
- Phase 1: three to five.
- Phase 2: four or more.

## 8. Risks

| Risk | Likelihood | What contains it |
| --- | --- | --- |
| Tesseract reads 1.4 mm text poorly, worst under foil glare | Medium | Gate S0, the glyph classifier, the guidance, and Retake per strip |
| Strip finding fails on fans and loose spreads | Medium to high | Straight-column guidance in v1, and fans in Phase 2 |
| Players don't follow the guidance | High | Refusals per photo with instructions; boxes and counts on the photo |
| Cards printed before Magic 2015 | Certain, for older collections | Needs you with name search in v1, and the title read in Phase 2 |
| Download size on phones | Medium | Loaded on the Scan page only and cached; OpenCV avoided |
| A wrong card is saved | Low, with §5 | Scans entries are not owned copies, and the crops are kept for review |
