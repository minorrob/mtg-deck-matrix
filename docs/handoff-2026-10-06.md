## 5. How to work here

- **Toolchain:**
  - Node 22 (the workflow's; Node 24 also works).
  - Playwright 1.56.0 with its Chromium: `npm install --no-save --no-package-lock playwright@1.56.0`.
  - Python with openpyxl.
  - wrangler 4.139.0 for `play-e2e`, as `WRANGLER=<path to wrangler.js>`.
- **The gate:** GitHub Actions (`.github/workflows/tests.yml`) runs every suite on each pull request since Rob made the
  repository public. `tools/local-ci.sh <ref> 2` is the same gate, run locally, when Actions cannot run.
  `tools/local-ci.sh HEAD 0` is the scan for secrets and personal addresses, required before every push.
  `./runtests.sh -q` runs the suites. A test that cannot fail is a comment: break the code and show each new check fail.
- **A card batch:** `game/tools/batch/README.md`.
  - The tools: `oracle-show.py`, a `cardlib.py` generator, `check-cards.mjs` (run with `node --stack-size=4000`), a
    suite per engine piece, and `breaks.py`.
  - Regenerate with `node game/tools/engine-definitions.mjs --write`, `node game/tools/engine-coverage.mjs --write`,
    `node game/tools/engine-catalog.mjs --write`, and `node tools/data-inventory.mjs` when a data file gains a reader.
  - README.md's suite list and its "There are N Node suites here" count are checked by `tests/data-integrity.mjs`.
  - **Clean room (ADR-001):** the Comprehensive Rules and Scryfall oracle text only. Never Forge's scripts. Cite CR
    numbers; never paste CR text.
- **Served files:** when a served file changes, bump its pins with `node tools/bump-pins.mjs <file>`, then the service
  worker and `crankmagic-app.js`, then `node tests/asset-versions.mjs --update`.
- **Staging release:** `WRANGLER=<wrangler.js> bash tools/release-staging.sh <a detached checkout of origin/main>`.
  - It builds, walks `release-acceptance` and `play-e2e`, commits and pushes `release/cloud-staging`.
  - Workers Builds deploys that push. Verify the deployment from the Cloudflare API: read
    `workers/scripts/crankmagic-staging/deployments`, then compare the deployed version's content with the release's
    bundle.
  - A push to `release/pages` is a production deploy. That is Rob's go, every time.
- **Browser walks against the live network in a proxied container:** Chromium needs the proxy's CA in its NSS store.
  Install `libnss3-tools`, then
  `certutil -d sql:$HOME/.pki/nssdb -A -t "C,," -n ccr-agent-proxy -i <the proxy CA>`. Never turn certificate checks
  off.
- **Commits:** clear messages that carry their reasoning and proof. Merge commits, not squashes. Never a model
  identifier in the repository.

## 8. The Train B card-list script (reproduce it anywhere)

```js
import {readFileSync} from "node:fs";
const R = process.cwd() + "/";
const {loadCardIndex} = await import(R + "game/tools/engine-cards.mjs");
const {missingFor} = await import(R + "game/tools/engine-constructs.mjs");
const inv = JSON.parse(readFileSync(R + "game/docs/engine-inventory.json", "utf8"));
const dir = loadCardIndex(), ready = [], blocked = [];
for (const [name, card] of Object.entries(inv.deck.perCard)) {
  if (dir.resolve(name)?.playable === true) continue;
  const miss = missingFor(card).map((m) => `${m.kind}:${m.name}`);
  (miss.length ? blocked : ready).push(miss.length ? {name, miss} : name);
}
console.log(JSON.stringify({ready, blocked}, null, 1));
```
