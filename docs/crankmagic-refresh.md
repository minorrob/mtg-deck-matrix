# Keeping CrankMagic current

Magic prints cards every few weeks. Prices move daily. EDHREC's play rates move
weekly. Every one of those changes lives in a **committed data file**, not in a
live API call, because the app is a static site that has to work on a phone with
no signal and must not depend on a third party being up when somebody opens it.

That is the trade: the app is fast and offline, and the data goes stale unless
somebody refreshes it. This is the list of what refreshing means, in the order it
has to happen, so a person — or the Claude skill this is written for — can do it
without knowing the rest of the codebase. **The runner is `tools/refresh.mjs`** (`--plan`,
`--check`, the run) and **the skill is `.claude/skills/crankmagic-refresh/SKILL.md`**: the
runner executes the order below, bumps the versions, and proves the result with the checks
listed under "What the plug-in has to produce"; the skill is the judgment around it — when
to run, what a failure means, what never to commit.

Everything here is a committed generator in `tools/` or `graph/ingest/`. **Nothing
in this document requires a model, an API key, or a paid call.** Scryfall and
EDHREC are public and free; the only cost is politeness (100 ms between requests).

## The ten files, and what goes stale in each

| File | Size | Holds | Regenerated by | Goes stale when |
|---|---|---|---|---|
| `data/commander-universe.json` | 1.6 MB | Every Commander-legal card by name, color identity, rarity, mana value, type, EDHREC rank, and whether it can be a commander. 31,830 rows. | `tools/commander-universe.mjs` | A set is released |
| `data/flavor-names.json` | 36 KB | The 513 cards printed under a name the rules do not use — "SpongeBob SquarePants" is Jodah, the Unifier. | `tools/flavor-names.mjs` | A Secret Lair or Universes Beyond set is released |
| `data/graph.json` | 38 MB (11 MB over the wire) | The whole format: 31,830 Commander-legal cards with the relationship fields the Discover graph is built from, EDHREC co-play for every one of the 3,411 legal commanders (701,916 links at 8%+ inclusion), and the bracket signal. Packed by `graph-payload.js`; `card-catalog.js` unpacks it. | `graph/ingest/*` for a full rebuild; `tools/graph-amplifiers.mjs --all` for a re-classify | A set is released, or `card-classify.js` changes |
| `data/commander-ranks.json` | 163 KB | EDHREC commander popularity, used to order the Deck Lab's picker. | `tools/commander-ranks.mjs` | Weekly, roughly |
| `data/cards.json` | 4 MB | The Card record set: identity, printed facts (rules text, mana cost, image), one dated price and the classifier's terms for the 2,131 cards the library, the six decks, the ladders and the guides name. | `tools/build-card-records.mjs --refresh` | A price moves enough to matter; a set changes a legality |
| `data/card-facts.json` | 485 KB | The name-keyed lens of the record set the simulator, the guides and the picture pop-ups read. | `tools/build-card-records.mjs` (with `cards.json`) | With `cards.json` |
| `data/graph-played.json` | 21 MB (on demand) | EDHREC co-play for every legal commander, split from `graph.json` so the terms load first. | `tools/graph-amplifiers.mjs` (with `graph.json`) | With `graph.json` |
| `data/commander-strategies.json` | 629 KB | The strategies each legal commander offers, derived from the graph's terms and the live decks' definitions. | `tools/commander-strategies.mjs` | With `graph.json` |
| `data/precons.json` | 408 KB (on demand) | Every Commander precon's hundred, from Wizards' decklists via MTGJSON, for Start from a precon; each name held to the universe. | `tools/build-precons.mjs` | When a precon is announced; with the universe |
| `data/deck-ratings.json` | 401 KB | Measured scores for the published ladders. | `tools/sim/` sweep | The engine generation changes |
| `data/deck-guides.json` | 7 KB | Hand-written how-to-play guides. | By hand; the rest are generated at read time by `guide-measured.js` | Never automatically |

## The order, and why it is an order

```
1. commander-universe.mjs        every legal card, by name
2. flavor-names.mjs              the names on the cards that are not those names
3. graph-amplifiers.mjs --all    re-classify the corpus with the current vocabulary
   (or the full graph/ingest/ chain when the CORPUS itself must grow)
4. commander-ranks.mjs           popularity, which orders every picker
5. build-card-records.mjs --refresh   the record set's prices, legality, text and images
6. commander-strategies.mjs      what each commander offers, from the refreshed terms
7. build-precons.mjs             every Commander precon from MTGJSON, its names held to the new universe
8. the derived files, each rebuilt from what steps 5 and 6 refreshed:
   build-advise-cards.mjs --write, build-commander-index.mjs, build-pilot-roles.mjs, reprice-variants.mjs
9. data-manifest.mjs, data-inventory.mjs   what the files now are
10. asset-versions.mjs --update  so browsers actually fetch what changed
11. runtests.sh                   every suite (the README says how many), several of which read these files directly
```

`node tools/refresh.mjs` is 1–10 in that order with the proof at the end; `--plan` prints
them, `--check` runs only the proofs.

**1 before 2** because the flavor-name table is checked against the universe: a
flavor name pointing at a card the universe does not carry is a broken alias, and
`tests/crankmagic-core.mjs` fails on it.

**2 before 3** is not required but is convenient — both talk to Scryfall and the
graph rebake is the long one.

**3 before 4** because ranks are joined onto cards by name.

**5 and 6 after 3** because the record set takes the graph's card block and the
strategies read the graph's terms.

**8 after 5 and 6** because each derived file is built from what they refreshed: the advisor's cards and the
variants' prices from `data/cards.json`, the commander index and the pilots' roles from the graph and the
strategies. Without it the proof fails `advisor`, `deck-autocreate`, `generators`, `pilot-roles` and `data-integrity`.

**9 after 8** so the manifest and the inventory see every file.

**10 is not optional.** Every data file is fetched with a `?v=` and served from the
browser cache. A changed file behind an unchanged version is a browser running last
month's data indefinitely with nothing on screen to say so. `tests/asset-versions.mjs`
refuses to record a changed file whose version has not moved, which is the guard
against exactly that.

## What a refresh run does, step by step

```sh
# 1-2. the two name tables (Scryfall, ~2 minutes)
node tools/commander-universe.mjs
node tools/flavor-names.mjs

# 3. re-classify the graph corpus with the current card-classify.js vocabulary.
#    Uses graph/.cache/oracle-text.json, refetching only what it lacks.
node tools/graph-amplifiers.mjs --all

#    ...or, when the CORPUS must grow to include a new set's cards, the full chain:
#    node graph/ingest/01-fetch.mjs && node graph/ingest/02-build-csv.mjs && …
#    See graph/README.md. That one needs Neo4j.

# 4. popularity
node tools/commander-ranks.mjs

# 5-6. the record set and the strategies, from the refreshed graph
node tools/build-card-records.mjs --refresh
node tools/commander-strategies.mjs

# 7. the precons, held to the refreshed universe
node tools/build-precons.mjs

# 8. the derived files, from the refreshed data
node tools/build-advise-cards.mjs --write
node tools/build-commander-index.mjs
node tools/build-pilot-roles.mjs
node tools/reprice-variants.mjs

# 9. what the files now are
node tools/data-manifest.mjs && node tools/data-inventory.mjs

# 10. bump every ?v= for the files that changed, in every page that names them,
#     then record the new hashes (tools/refresh.mjs does the bumps for you)
node tests/asset-versions.mjs --update

# 11. prove it
bash runtests.sh -q
```

Or, all of it in order with the proof: `node tools/refresh.mjs`.

### The derived files (in the runner's plan since 2026-10-30)

Four more files are derived from the data files, each by its own generator. The proof fails five suites until they
are rebuilt (found on the 2026-10-29 refresh, PR 948), so `tools/refresh.mjs` runs them as step 8, marked `derived`
in its plan (three are artifacts outside the schema registry, and the commander index is a registered data file; each tool vouches for its own file and names it):

| Generator | Writes | Red without it |
|---|---|---|
| `node tools/build-advise-cards.mjs --write` | `cloud/advise-cards.mjs` | `advisor` |
| `node tools/build-commander-index.mjs` | `data/commander-index.json` | `deck-autocreate`, `generators` |
| `node tools/build-pilot-roles.mjs` | `game/engine/pilots/roles-data.mjs` (the engine lane's tree; say so in the PR) | `pilot-roles` |
| `node tools/reprice-variants.mjs` | `data/archive/variants.json` | `data-integrity` |

`data/commander-index.json` is served, so it is in the schema registry (`commander-index@1`, stamped `compiledAt` with the date of the data it is compiled from, so `--check` stays exact) and therefore in the manifest, which `tests/data-manifest.mjs` requires of every URL the asset map serves. Its URL lives in the asset map (`commanderIndex` in `crankmagic-assets.js`,
and the worker's on-demand list), which `crankmagic-newdeck.js` reads, so the runner's bumper finds it and moves its
`?v=` with the rest. Before 2026-10-30 the URL was hard-coded inside newdeck, the bumper reported 0 references, and
the cascade moved for nothing.

What else the 2026-10-29 refresh taught:

- **A card the catalog rule drops shrinks the universe on purpose.** The guard stops the run. Commit the universe
  alone, say so in the PR, and re-run the runner from that baseline; the guard stays as it is.
- **Prices move, and a price-sensitive assertion can flip.** `crankmagic-lobby` pinned that a bracket-fitted deck
  costs no more than the unfitted one; Rob removed that clause (the bracket keeps decks in one weight class).
  Re-price the variants, and ask before changing any other assertion.
- **The Tests job on a ready PR can be canceled at its 60-minute limit** (it was, 23:23 to 00:23 UTC). Then the gate
  is a full local run (`node tools/run-suites.mjs -q`, about 75 minutes on four cores; start it detached, with its
  output to a file, so a container restart cannot take it) accounted against a clean `origin/main`. Fifteen board and
  browser suites fail the same way on main in a cloud container (PR 948 lists them); nothing else may.
- **The Menu's graph row reads the graph's `amplifiersAt`** (when it was last re-classified), falling back to
  `generatedAt` (the corpus bake), and says "not loaded yet" until a page loads the graph (Discover, the Lab, New deck,
  the Play draft). Only the Neo4j ingest moves `generatedAt`, and only it adds a card to the corpus (86 commanders are
  missing from `graph.json`, ROB-214; "Name Sticker" Goblin is still in the graph and the engine's tables).

### Bumping versions

`crankmagic-assets.js` holds the data URLs; `crankmagic-sw.js` holds the offline
inventory. **One file, one version, everywhere** — the test enforces it and names any
file that disagrees. `tools/refresh.mjs` moves the versions of the served data files that
changed and the cascade below; nothing is bumped for a file that did not change.
Changing a data URL changes `crankmagic-assets.js`, which changes the service
worker's file list, which means the service worker's own registration version in
`crankmagic-app.js` moves too. The cascade is:

```
data/<file>.json?v=N+1        in crankmagic-assets.js, crankmagic-sw.js
crankmagic-assets.js?v=N+1    in index.html, crankmagic.html, crankmagic-sw.js
crankmagic-app.js?v=N+1       in index.html, crankmagic.html, crankmagic-sw.js
crankmagic-sw.js?v=N+1        in crankmagic-app.js (the registration line)
```

## What the plug-in has to produce

A refresh is finished when all of this is true. These are the acceptance criteria,
not a wish list — each one is checked by a suite that already exists, and
`tools/refresh.mjs` runs them as its proof (`tests/refresh.mjs` holds the runner's plan to
this order and to the registry).

1. **Every Commander-legal card is in `commander-universe.json`.** Its `counts.cards`
   should grow by roughly a set's worth, never shrink. A shrink means the Scryfall
   query changed meaning and the run should be discarded.
2. **Every flavor name points at a card in the universe.** Zero orphans.
   (`tests/crankmagic-core.mjs`)
3. **Every graph card carries all ten classified fields** — roles, requires, causes,
   triggers, produces, multiplies, grants, extends, mechanics, tribes — and re-deriving
   them from rules text reproduces the file exactly. (`tests/card-classify.mjs`)
4. **Both sides of every relation are populated.** A term that only one side ever
   names is a filter nobody can walk. (`tests/crankmagic-graph.mjs`)
5. **Every card has a bracket signal or none, correctly.** Game Changers come from
   Scryfall's own `game_changer` flag, never from a regex.
6. **Every asset has exactly one version, and every changed file has a new one.**
   (`tests/asset-versions.mjs`)
7. **Every suite passes.** (`bash runtests.sh -q`; the README names the count)
8. **The README's suite count matches.** (`tests/data-integrity.mjs`)

## What a refresh must never do

- **Never invent a card.** Every row in every generated file traces to a Scryfall
  response. If a fetch fails, the run keeps the previous value and says which cards
  it could not reach — a missing field and a false one look identical in JSON, and
  the difference is sometimes a whole bracket.
- **Never touch `data/active-state.json` or anything under `sim/`.** Those are the
  reader's own library and measured results. A catalog refresh is not a state change.
- **Never rewrite `data/deck-ratings.json` without re-running the sweep.** A score
  is a claim about a protocol and an exact list; carrying one forward onto a
  different list is the one dishonesty this codebase is built to prevent.
- **Never put a card in the catalog that is not a Commander-legal paper card** (Rob,
  2026-10-29; `tools/catalog-rule.mjs`). Scryfall's Commander legality must be "legal",
  the name must not begin "A-" (an Arena rebalance), and the card must have a paper
  printing. A bulk row's `digital` flag is not that test: it describes one printing.
  `tests/catalog-rule.mjs` holds the loaders and the committed catalogs to it. A refresh
  that drops a card for this reason is a shrink on purpose; say so in the pull request.
- **Never bump a version without changing the file, or change a file without
  bumping.** The first wastes everybody's cache; the second poisons it.

## Prices, and why they are the odd one out

Prices are the only thing here that moves daily, and they are deliberately **not**
baked on a schedule. `card-catalog.js` fetches the lowest-cost paper printing live
when a card is inspected (`details()` → `cheapest()`), so the number a reader is
about to spend money on is fetched at the moment they look at it, not read off a
month-old snapshot. The baked prices in `cards.json` and `graph.json` are for
budget arithmetic in the draft builder, where being a month stale changes a total by
a few percent and being offline would change it by everything.

Scryfall's `usd` figures are TCGplayer-sourced. There is no open anonymous TCGplayer
API to use instead — theirs needs a seller or partner key — so the cheapest-printing
search *is* that data, reached through the API that can actually be called.
