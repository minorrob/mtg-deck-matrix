## Method, and five things it stopped me filing

Every candidate finding in this run was checked a second way before it was written down. That
caught **five false positives**, each of which would have been a real-looking bug report:

| Looked like | Actually |
|---|---|
| `#discover` renders an empty `<main>` | The read fired before the view painted. Explore is fine. |
| Three unnamed form controls (a11y) | All three are wrapped in `<label>` elements with real text. Fine. |
| The `+New deck` link does nothing | It works on click; a handler intercepts it. Only the **deep link** fails. |
| The board's View options has no Sound section | It is there, in its correct pre-gesture state. My selector missed a `<strong>`. |
| The Panel button does not toggle back | It does; the label flips `▸`/`◂` so my second lookup missed it. |

**The lesson is worth keeping**: a UAT that reports races and selector misses as defects costs more
than it finds. Every automated read here now polls for a real signal rather than sleeping a guess.

## Findings

Severity follows the 2026-09-21 convention. IDs are new (`U-`) because no existing ID covers these.

### U-05 · S1 · The two lobbies do not mirror. They are different tables.

**Rob asked for this by name.** They are the same code and they look alike, so it reads as one
table seen twice. It is not.

While the host was serving a live table with a guest seat open, the cloud lobby was showing a
**different four seats entirely**:

| | Local (the real table) | Cloud (at the same moment) |
|---|---|---|
| Seat 1 | Rob · human · occupied | "Seat 1 · You" · Atraxa · $154.98 |
| Seat 2 | **UAT Guest · human · UNOCCUPIED, invitation open** | AI · Shadrix · $99.21 |
| Seat 3 | Atraxa · AI | AI · Quintorius · $90.24 |
| Seat 4 | Shadrix · AI | AI |
| Remote guests | **on**, tunnel live and answering publicly | **"Remote guests off"** |

The cloud copy is a local-storage mock of a lobby. It has seats, brackets, costs, a countdown and
a Start button, and **none of it is connected to anything**. A person moving between the two
surfaces has no way to tell which one is real.

This is the root that U-02, U-04 and HAND-06/07/08 all grow from, and it is what
`docs/plan-web-to-local-table-2026-09-21.md` pieces 1–3 were written to fix.

### U-03 · WITHDRAWN · the second host link is deliberate

Filed as "the cloud lobby shows the local host link twice". Reading the source in order to fix it
showed the second one renders **only when `hostReachable === false`** — a note telling a reader on
a copy with no host where the game actually runs. The Table rules row states the address; the note
says what to do about it. Two links, two jobs.

No change made. That is **six false positives** on this run: five caught before filing, and this
one caught before changing behavior that was already correct — the more expensive kind to miss.

### U-02 · S2 · A "Start the game" button that says in its own copy that it does not work

**Corrected while fixing it.** The button is not non-functional; it is correctly `disabled` when
the table cannot start. The defect is the note beside it. `startWhy` is deliberately **empty when
the table is ready**, because its job is to name a blocker, and the template read
`startWhy || "The board is not built yet…"`. So the discouraging sentence appeared **exactly when
the button worked** and never when it did not. I filed the button on the strength of its own copy,
which is what any reader would have done.

On **both** platforms, below the pod summary:

> Turn order is shuffled when the game starts. **[Start the game]** The board is not built yet.
> This button will deal the first hands once it is.

The button is **enabled**. Rob's standing rule of 2026-09-22 is that nothing is available before it
is functional; this is a control that announces its own inoperability and remains clickable.

### U-04 · S2 · The cloud claims a game is starting that cannot start

Cloud: **"Every seat is ready. Starting…"** beside an enabled `Start` button.
Local, same moment, same code: **"Starting in 10…"** beside a `Stop` button — a real countdown.

The cloud has no host and cannot start anything. `docs/plan-web-to-local-table-2026-09-21.md`
says a copy that cannot reach a host "refuses to count down and says so". **It does not refuse.**
Piece 2 of that plan turns this into **Send Local**.

### U-03 · S3 · The cloud lobby shows the local host link twice

`127.0.0.1:8768` in Table rules **and** `http://127.0.0.1:8768/` below it, both `target="_blank"`.
Local shows one. Two controls for one destination, on the copy where the link is least likely to
be reachable.

### U-01 · S3 · `#new` is an href but not a route

The Decks view renders `<a href="#new">+New deck</a>`. Clicking it works, because a handler
intercepts. **Navigating to `#new`** — a bookmark, a shared link, middle-click, open-in-new-tab —
lands on Decks with no wizard and no message. Either make `#new` a route or stop advertising it as
a URL.

### U-06 · S3 · Disabled view toggles with no reason given

`Sheet` is disabled on **To buy**; `Sheet` and `Table` are both disabled on **Orders**. Nothing
says why. If those views cannot apply to those tabs, the control should say so on hover or not be
rendered.

### U-07 · S3 · The live board carries controls that leave or reconfigure the game

BRD-18 asked whether the local board holds only what gameplay needs. Eleven header controls during

### U-12 · S1 · A failed engine launch strands the table forever, in silence

**The scenario Rob described — invite a friend, fill the rest with AI — cannot recover from a
single failed launch.** An agent playing a real guest was stranded for nine minutes with no error
of any kind.

**The mechanism, read from the source and confirmed against the live table.**
`game/contracts/table-lifecycle.mjs:65`:

```js
case 'engine-failed':
  t.phase='selecting'; t.launchId=null; t.seats.forEach(s=>s.ready=false); break;
```

Every seat is cleared, **including the AI seats**. AI readiness is granted in exactly two places —
`local-table-runtime.mjs:20` when the table is built, and lines 83/93 on a **rematch**. Nothing
re-readies an AI seat after `engine-failed`. The table therefore sits in `selecting` forever,
blocked by two bots that no one can ready: there is no host control for it and the guest has only
"Not ready" and "Exit the table".

The author clearly knew AI seats need special handling on a reset — `case 'completed'` two lines
below does `s.rematch = s.kind==='ai' ? true : null`. `engine-failed` was written without it.

**Confirmed, not inferred.** The live table read:

```
phase: selecting   generation: 1   launchId: null
seat 0 human ready=n   seat 1 human ready=Y   seat 2 ai ready=n   seat 3 ai ready=n
```

`generation` starts at `0` and increments only on launch. `generation: 1` with `phase: selecting`
and `launchId: null` **is** the `engine-failed` end state. And with both humans then marked ready,
the table still would not start — watched for 24s, `0:R 1:R 2:- 3:-`, phase never moved.

**It fails silently.** No toast, no console error, no failed request — the guest agent checked all
three. The only trace is an orange line reading "Starting the rules engine" that never changes,
and `local-table-runtime.mjs:59` holds the real reason where nobody can see it: *"Forge did not
become ready within four minutes."*

**Why the launch failed is the part U-05 pays for.** `/api/live` showed a *different* match
`starting` at the time — one the mock lobby's own countdown had launched. Two lobbies, one engine.

### U-11 · S2 · The production release gate cannot run on this machine

`tests/uat/journeys.mjs` is the repo's own release gate. Its README calls it required: *"A missing
browser/server fails the release gate."* Run today:

```
browser-geometry: 139 checks passed   ← this half is healthy
Error: ENOENT: no such file or directory,
  open 'C:\home\user\mtg-deck-matrix\data\cards.json'
  at tests/uat/scryfall-stub.mjs:8
Browser release gate failed: crankmagic-journeys.mjs
```

`tests/uat/scryfall-stub.mjs` lines 8 and 9 read **two hardcoded absolute paths** from some other
environment:

```js
const CARDS = JSON.parse(readFileSync("/home/user/mtg-deck-matrix/data/cards.json", "utf8")).cards;
const NOT_FOUND = readFileSync("/home/user/mtg-deck-matrix/tests/fixtures/scryfall-flavor-name.json", "utf8");
```

On Windows those resolve to `C:\home\user\…` and do not exist. So **new-user assembly, exact
prints, source correction, concurrency, quota abort, backup/restore, construction, graph, offline
and mobile are all unrunnable here**, along with `tour-walk.mjs` behind them, which never gets to
start.

The geometry half runs and passes, which is why this has stayed invisible: the gate prints a
confident green line before it dies.

The fix is small — resolve both against the repo root the way every other suite does (`ROOT` from
`schema/index.mjs`, or `new URL(..., import.meta.url)`). The value is not the fix; it is that a
large, well-written body of journey coverage has been sitting unrunnable, and no amount of manual
walking substitutes for it.

### U-13 · S2 · The guest lobby, as a first-time guest actually meets it

Reported by an agent briefed to behave like a friend who has never seen the app. Quoted from its
screen, not paraphrased.

- **Status and commander run together with no separator.** Seat cards literally render
  `"Choosing a deckChulane, Teller of Tales"`, `"ReadyPurphoros, God of the Forge"`. Every seat
  card, every state.
- **One player, two contradictory statuses, on screen at once.** Rob's card said "Choosing a deck"
  while the strip directly below said "Deck chosen, not ready".
- **Two player lists with three vocabularies for one thing.** The AI seats were described as
  "Choosing a deck", "Preparing" and "not ready" simultaneously.
- **"Starting the rules engine"** sat unchanged in orange for nine minutes. No spinner, no
  timestamp — unreadable as live status, stuck process, or decoration.
- **"You (no validated deck)"** — "validated" is developer vocabulary.
- **"Choose this deck again or replace it"** as a heading after success reads like something went
  wrong.
- **No confirmation after a deck is accepted.** No card count, no cost — on a table that advertises
  a $225 cap. The guest never learned whether their deck fit.
- **"bracket 3" is never explained**, and neither is the Base / Tuned / Pod Fun / Max axis the 184
  preloaded decks are sliced on.
- **"Ready to play" is disabled with no reason given** until a deck validates.
- **A "Deck name" box stays visible and empty** when a preloaded deck is selected; it looks
  required, does nothing.
- **The lobby re-renders its whole DOM about once a second.** A native dropdown open during a poll
  is liable to be replaced under the user mid-selection — the agent had to re-acquire elements
  repeatedly.

None of this blocks a competent user. All of it is what a friend meets in their first two minutes.

### U-10 · S2 · The cloud cannot reach the gateway, and the mechanism to let it is built and switched off

Measured from the real origin against the live tunnel, not inferred. Run in the page at
`https://minorrob.github.io`:

```
GET  /health      → TypeError: Failed to fetch
GET  /api/setup   → TypeError: Failed to fetch
POST /api/prepare → TypeError: Failed to fetch
```

`/health` returns `200` to `curl` from the same machine, so the gateway is serving. The browser is
blocking the response: no `Access-Control-Allow-Origin` for that origin.

**And the gateway already knows how to grant it.** `createGuestGateway` takes a `webOrigin` — "the
one web lobby this gateway will answer" — validates it to scheme and host so a path cannot smuggle
anything past the comparison, and emits `Access-Control-Allow-Origin` plus a proper `OPTIONS`
preflight for exactly that origin. `serve-review.mjs:120` wires it to `COMMANDER_WEB_ORIGIN`.

**Nothing ever sets that variable.** `start-crankmagic.ps1` has no parameter for it and never
passes it.

So pieces 1 and 2 of the web-to-local plan are not blocked on building a CORS story — the story is
written. They are blocked on a launcher flag. That changes the size of the remediation
considerably, and it is the **third** capability found this way today, after `--table-viewport`
(the board's real viewport height, posted and discarded) and `CrankMagicReturnChannel@1` (the
deck-handoff return path, written and never read).

### U-08 · S4 · A fresh table reports the previous table's phase

`/api/start` returned `phase: "countdown"` for a table that was, a second later and correctly,
`selecting` with an unoccupied seat. Cosmetic, but it is the kind of stale read that makes a
"the table started without me" report impossible to trust.

### U-09 · S2 · The local lobby self-starts on a ten-second countdown

Once every seat reports ready, the local table begins a 10s countdown and starts. During this run
it started a four-player game while I was reading the page; the `Stop` control was gone before the
click landed. For an all-AI table that is convenient. With an invited human still choosing a deck
it is the difference between a game and an abandoned friend — which is what makes U-05's
unoccupied-seat handling worth confirming rather than assuming.
