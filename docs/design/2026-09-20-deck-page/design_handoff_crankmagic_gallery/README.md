# Handoff: CrankMagic "Gallery" redesign — Decks, Deck page, Library, Explore

## Overview
A visual and layout redesign of CrankMagic (github.com/minorrob/mtg-deck-matrix, `main`), the private Commander deck workshop. The brief: the app was monochromatic dark blue; make it warmer, more joyous and better laid out, with commander art front and centre and each deck tinted by its mana identity. Information architecture is unchanged — same pages, tabs, actions, counts and vocabulary as the README and the `crankmagic-*.js` modules — but what is shown on each page was rethought (see "Screens").

Five screens are hi-fi here; the rest of the app (Play, deck sub-tabs, To buy/Orders/Sheet, Ready to add, Make the change) should follow the same system using the tokens and patterns below. Lo-fi wireframes for those pages are in `wireframes/Wireframes.dc.html`: turn 1 (1a The hundred · 1b Upgrades · 1c Acquire · 1d To buy · 1e Orders · 1f Sheet · 1g Ready to add · 1h Make the change · 1i Play), turn 2 Play (2a form · **2b table-first — chosen** · 2c dashboard · 2d Change deck · 2e Game canvas), turn 3 (the six mat elements, `wireframes/Sea Options.dc.html`), turn 4 dialogs and remaining surfaces (4a Card pop-up · 4b Review receipt · 4c Log a game · 4d Ordered… · 4e Columns · 4f Guide & SWOT · 4g How a deck comes together · 4h Archived + Compare). They are **low-fidelity**: follow their structure and content order, style them with the tokens below and the patterns of the five hi-fi screens.

## About the design files
Everything in `screens/` is a **design reference written in HTML** (a streaming "Design Component" format: a template plus a small logic class, mounted by `support.js`). They show the intended look and behaviour. **Do not ship them.** Recreate them inside the existing app — plain HTML/CSS/JS, no framework, no build step (see `AGENTS.md` and README "Run") — by editing `crankmagic.css` / `crankmagic-design.css` and the render functions in `crankmagic-decks.js`, `crankmagic-collection.js`, `crankmagic-discover.js`, and the shell in `index.html`. Keep the app's tests green (`bash runtests.sh -q`, `tests/page-budget.mjs`, `tests/browser-geometry.mjs`) — the page budget holds word/control counts before the first table, so keep new chrome lean.

Open any screen file directly in a browser to see it (serve the folder over HTTP; fonts and `assets/` are relative). Each screen has a `theme` prop (`dark` | `light`); Deck Page and Explore also take `layout` (`desktop` | `phone`). The values are in each file's `renderVals()` — read them for exact hexes.

## Fidelity
**High-fidelity.** Colours, type, spacing, radii and copy are final. Recreate pixel-close. Data shown is Rob's real live library (`data/live-load.json`) as of 19 Sep 2026; treat figures as sample values, not constants.

## Interactions & state
**Play lobby (table-first, wireframe 2b).** The table is one full-width container (main minus rail) split into four quadrants, one per seat, in the order they sit (2 · 3 / 4 · 1, you bottom-right). Once a seat has a commander, a **90° fan** radiates from the quadrant's inner corner (the one touching the centre panel) outward to the player's edges, one wedge per colour of the commander's identity in WUBRG order (`--mana-*`, ~60% opacity, 1px light seam between wedges; a mono-colour commander is a single wash, no seams), drawn as an SVG overlay above the status element and below the text. Each quadrant is filled with the animated element for that seat's status — empty seat = mist, invite sent = wheat, pending acceptance = wheat (darker), pending deck = ocean, ready = leaves, error = fire (`screens/table-sea.js`, one fixed element per canvas, ~80% opacity under a dark top/bottom gradient) — and carries the seat label top-left, a status pill top-right, and at the foot the commander card — full quadrant height minus the label row (488:680, so ≈ 95×132 at a 170px quadrant), in the outer corner, an empty dashed frame until a deck is chosen; click opens the card pop-up for any player — beside one line of detail (commander · style · difficulty · pilot, or invite address · expiry · resend · QR, or deck · bracket · cost · Change deck). Centred over all four, ~30% of the width, a white panel — the wand-and-gear logo stamped in its bottom-right corner at ~7% opacity, greyscale, bleeding off the edge, purely decorative — holds the **Table rules** (bracket, deck cost cap, AI pilot default, remote guests; edit ▾) and a read-only launch line ("Launches when all four are ready · 2 to go"). **All player actions live on the player's own quadrant** — Change deck, Ready / Not ready, Leave seat; the host additionally gets Invite (email / QR) on an empty quadrant and the AI seat configurator (commander, style, difficulty, pilot) on AI quadrants. Every other quadrant and the centre panel are static to that player and only reflect system state. There is no Launch button: the table starts itself with the 10 s countdown once all four seats report ready (`GET /api/table/readiness` empty), Forge starting with the clock. Host-only controls (table rules, End table, force-advance) sit under **Host tools ▾** in the action row, never on the table. No separate "who is the table waiting on" list — the quadrants are it. Prepare decks runs automatically per seat once its deck is chosen (that seat shows "Pending deck" while resolving). Host doctor status stays as the strip above the table.

**The action row follows the tab.** The primary and its two companions change with the deck-page tab: Overview = the state's primary (Ready to add / Buy list / Log a game) + Log a game + Make the change; The hundred = Edit card list · Card status ▾; Upgrades = Promote ticked (n) · Link an upgrade…; Acquire = Buy list (n) · View orders; Explore = Open Discover with this deck · Trace. `More ▾` and Measure stay on every tab. On a phone the sticky bottom bar mirrors the current tab's three.

**The Sheet is a spreadsheet.** Every numeric cell (Own, Ordered, Bench, Buy, each deck's T and A) is directly editable in place: at rest it wears a faint dashed border; on focus a 2px brass (`--color-accent`) ring and a warm fill; the cell is a real `<input inputmode="numeric">` or `contenteditable`, not a click-to-open dialog. Enter commits and moves down, Tab right, Escape reverts, arrow keys walk cells, typing replaces the value. A plain raise of Own or Ordered saves immediately; a change that takes a copy from another deck goes through the existing review dialog first (the sheet keeps the cell in the editing state until the dialog resolves). `+n` and `ˢn` markers stay as superscripts and are not editable. Keep the Card column frozen and the header sticky. This is the highest-priority behaviour on the Library → Sheet view.

**Rows are one line tall.** Table rows never wrap: cells ellipsize, actions are a single short verb plus ⋯ (e.g. `Arrived` · `⋯`, not `Arrived → bench` · `Lines`), and the action column is sized to fit them. Secondary actions live in the ⋯ menu.

**Sortable headers, everywhere.** Every table column header is a button: first click sorts A–Z (text) or high→low (numbers, prices, counts) and shows ▴; second click reverses (▾); other columns show a faint ⇅. Applies to Library (all views), To buy, Orders, The hundred, Upgrade path, Ready to add, Make the change, Explore List, and the game record. The existing `.cm-sort-head` / `v-sort-head` pattern is the hook.

**Tables span the content width and every table has a header.** Tables and lists run the full width of `main` (page minus the 216px rail), not a column of a bento. Every table — including quick-look tables such as The hundred, the Upgrade path, the game record — has a sortable header row. **Quick-look tables link to their owner.** Where a page shows a read-only or abbreviated view of data another page owns (The hundred → Library filtered to the deck; Acquire → To buy; deck Record → Play), the table header carries a right-aligned link "Open in <page> →" to that page with the scope applied.

**Panels grow with their rows.** No list, table or working-list container gets a `max-height` or an inner scrollbar. It extends downward to fit every row; the page scrolls. The only exceptions are pickers inside dialogs (commander picker, facet dialogs), which may scroll internally once they would exceed the viewport. Paging (60 / 120 / All) remains the way to cap very long tables. Remove existing caps such as `.cm-facet-list{max-height}` only where they sit on a page, not in a dialog.
Unchanged from the app: routes `#decks`, `#decks?deck=&tab=`, `#cards?tab=&view=`, `#discover?deck=&trace=1`; theme is a new `data-theme="light"|"dark"` on `#matrix-v2`, remembered with preferences (default dark). Tile click → deck page; count tile click → status filter (toggle); filter chip × → clears that filter; door cards → pick deck+role / commander picker / focus search; all existing dialogs, menus, undo, and the `?` help bodies stay.

## Extrapolating to pages not drawn
Anything not in `screens/` or the wireframes (Lab/Build, Discover List and Trace panes in full, the Tabletop view, User Functions, Tour, Share, import/export dialogs, the tabletop "Table" view of Library, phone layouts of the wireframed pages) follows these rules — apply them in order and the page will belong:

1. **Shell first.** 216px rail with the aether wordmark, current page raised, its sub-pages indented (deck sub-pages under the open deck; Library · To buy · Orders · Sheet under Library; Graph · List · Trace · Role lens under Explore). Main padding 28px 36px 48px. No top header bar; Share / Feedback / User Functions live under the rail-foot **Menu ▾**.
2. **One head, one primary.** h1 in Young Serif 44–56px, one muted summary sentence with the two or three figures that matter in ink weight 600; at right ≤ 3 buttons — one brass (dark) / felt (light) primary, the rest outlined 12px-radius — plus **More ▾**. The primary is the state's next action, not a fixed slot. Actions change with the tab (see "The action row follows the tab").
3. **Tabs as a segmented control** (panel bg, 14px radius, 4px pad, selected = raised + 700, counts as small in status colour). Views (List · Sheet · Table) are a second segment right-aligned on the same row.
4. **Counts as tiles, not a ribbon.** A row of equal tiles (`repeat(n, minmax(0,1fr))`, gap 8px): 26px display figure in its status colour, dot + 12px label; tiles that filter show their border in that colour when active. One caption line under the row states the equation.
5. **Filters in view, the rest folded.** Search 42px in a panel-bg field, up to five dropdown buttons showing "Label value ▾" (the set one tinted by the scope colour), dashed "More filters", Group ▾, Columns. Active filters as removable chips with Clear all.
6. **Tables.** Full content width, panel card radius 18px, 11px uppercase sortable header (▴/▾, ⇅ on unsorted), 56px rows that never wrap, name in 700 with the Primary Purpose chip under it, every card with its mana pips (colourless {C}, lands with the land mark), status as a pill in its hue, one verb per row + ⋯, group bands tinted by their scope. Quick-look tables link to their owner page. Panels grow with rows; no inner scroll outside dialogs.
7. **Cards and bentos.** Overview-type pages are a 6-column bento of panel cards (radius 18px, padding 22px) with an uppercase 12px label; one tinted "Next" card on top spanning the width. Phone: every card spans 6.
8. **Deck tint.** Anything scoped to a deck takes `--tint` = the commander's first colour: chips, group bands, the Next card gradient, the hero glow, the readiness bar's context. Multi-colour identity is a fan (Play) or first-colour tint (everywhere else).
9. **Dialogs.** 900px max, 25px padding, sticky title with ×, 2-column form grid (`.cm-form-grid`), inputs in `--color-raised` with 12px radius, one primary bottom-right, secondary beside it. Any action that changes a deck, reservation or money shows the receipt table (4b) first. The card pop-up (4a) is the one place rules text is printed; elsewhere the card image is the rules.
10. **Empty states** are a dashed-border card with one sentence and the one action that fills it (see Record on the deck page).
11. **Motion.** Lift on hover (250ms), bars from zero on load, aether mist on the wordmark only, the living mat only on Play; `prefers-reduced-motion` disables all of it.
12. **Copy.** Plain declarative sentences, no exclamation marks, figures said once, verbs with counts ("Buy list · 13").

Where an existing page has a pattern this guide does not name (the Lab's run panel and orbs, the Discover canvas modes, the Tabletop piles), keep its structure and restyle it with the tokens: surfaces to the three planes, accents to brass/felt, blue only where it means aether, radii to 12/18/22, Young Serif for headings and figures, Satoshi for the rest.

## Play — chosen direction (2b) summary for implementation
- Full-width table container split into four seat quadrants (2 · 3 / 4 · 1, host bottom-right), each filled with the status element (`table-sea.js`) and, once a commander is chosen, the colour-identity fan radiating from the quadrant's inner corner. Seat label + status pill in the outer top corner; full-height commander card + detail column in the outer bottom corner; the player's own actions (Change deck · Ready/Not ready · Leave seat; host: Invite, AI seat config) live only on their quadrant.
- Centre panel (~26% width): Table rules, read-only to players, faint logo stamp, "Launches when all four are ready · n to go". Auto-launch with the 10 s countdown; host tools under **Host tools ▾**.
- Change deck (2d) opens over the table: deck strip with colours/bracket/real-in-box bar, Saved deck · Lab list · Bring a list, snapshot + Forge support summary, one primary "Use <deck> at Seat n".
- In game (2e): **the play surface is 100% of the window.** The rail is hidden and returns as an overlay from ☰; the right panel (Card · Tracker · History · Combat) is closed by default and slides over the mat from **Panel ▸**; neither ever narrows the mat.
