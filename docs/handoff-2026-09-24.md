## Board geometry — the part that took the longest

**The measurement that started it (proven, and re-checkable):** with a game running, drive
`/review` at 1920×1080 and read the boxes. It gave:

| | was | now |
|---|---|---|
| Mat ratio | **2.92** | 1.69 (1020/603) |
| Mat | 517×177 | takes its height from its width |
| Board chrome | heading 28 + **mana band 70** of 300 | heading only |
| Hand card | 152×212 | 68×95 (frame's 34×46 doubled) |
| Seat | 427×240 | 533×300 |
| Mat width | 917 | 1131 |

Two defects, neither of them taste:

- **The mat was flex-shrunk out of its own aspect ratio.** `.seat` is a column flex box, the mat is
  a flex item, and `flex-shrink` beats `aspect-ratio`. `flex:0 0 auto` stops it.
- **The six-box mana band is in no frame and no plan** — checked `plan-stage-b-board.md`,
  `ACTIVE.md`, `plan-board-information-layer.md`. It was 70px of a 300px board. Focus keeps it.

**B.6b, the History band — proven** by `node tests/wireframe-conformance.mjs` and a live pod.
`alignToPiles()` measures the column after layout: the band takes Command's left edge, Exile's
right edge and the height actually free. Playmat layouts move the piles (Command 38% by default,
33% gold, 34% violet, 35% moon, 18% lotus), so fixed percentages were wrong — a live gold mat had
the band overhanging Command by 3%. Lotus has no room and hides it rather than drawing a sliver.

**One card size — proven** by the conformance check "every card on the mat takes its width from one
variable". Four widths were in play and agreed nowhere. Note the check caught the first attempt:
the new rule was added and the three it replaced were left underneath it, out-weighed rather than
removed — trap 2 in `docs/INDEX-where-things-live.md`, which is how four accumulated.

**Trap 1 caught three separate changes today** (`#cm-dialog` beat `dialog.cm-picker-dialog`;
`#matrix-v2 :is(p){margin:0}` beat two attempts at the wizard's lede). Carry the id.

## Outstanding, with the reason

1. **The local host 404s the new logo.** `serve-review.mjs` builds its file list from `git ls-files`
   **at startup**, so a host started before the file existed cannot serve it. Proven:
   `curl -o /dev/null -w "%{http_code}" http://127.0.0.1:8768/app/assets/crankmagic/crankmagic-logo-gear-v4-256.webp`
   returns 404 while the old name returns 200. **A restart fixes it. Not done because Rob had a
   game running on that host.**

2. **The new table design is extracted but not built.** `docs/design/2026-09-24-table/` holds the
   handoff; `Play Focus Mock.dc.html` is the reference. Numbers read out of it: board cards
   **112×156** (tapped 156×112), hand cards **140×195**, hover **`transform:scale(2.4)`** with
   origin `50% 100%` and `z-index:60`, canvas 1920×1080, left pane 168px, board section 1420×799,
   History at `grid-column:2/span 2; grid-row:3` with `background:rgba(10,9,8,.55)` and no border.
   **This supersedes the option-2 History placement** decided on the 23rd — the new design has room
   between the pairs where the old one did not.

3. **The local host is not the app's lobby, and Rob believes it is.** This is the one thing worth
   reading twice. `cm-lobby-table` — the 2b pre-lobby with seats, commanders, Ready Up and Host
   tools — appears **0 times** in `game/ui/setup.mjs` and `game/ui/review.mjs`; it lives only in
   `crankmagic-game.js`. The local host has always run its own older form. `70fd4db` gives that
   form the SHAPE he asked for (rules, then "Set up game", then seats) out of pieces that exist
   there. It does not make it the app's lobby. That work is
   `docs/plan-web-to-local-table-2026-09-21.md`, recorded in `ACTIVE.md` as five pieces, none
   started.

4. **The Load pane shows no decks, and the cause is unconfirmed.** Export/import of a deck file is
   built (`CrankMagicDecks@1`, in the Load pane's footer). My best explanation is that IndexedDB is
   per ORIGIN, so decks made at `127.0.0.1:8768/app/` are not visible at the github.io copy.
   **Assumed, not proven** — three attempts to seed a test browser failed and I could not reach one
   holding Rob's decks. If the footer's Export also reports "no decks to export", that confirms it.

5. **The horizontal scroll for a zone that outgrows two rows is not built.** This is the real fix
   for "the card default size is too big for 2 rows", not shrinking cards. A height cap was tried
   and reverted: `game/tests/card-layout.test.mjs` holds that the compact size packs six columns
   and three rows and that the large size shows fewer columns than the compact one, and a card that
   cannot grow past a height ceiling never reduces the column count. The test was right and the
   lever was wrong.

6. **Two-row fit never seen with real creatures.** The arithmetic and the measured 381px inner

7. **Mat templates from the playmat art.** `game/ui/playmats.mjs` already maps 9 mats to 5 layouts
